## 刷流汇总（BrushDigest）

开了「站点刷流」插件，手机大概率是这种状态：

```
【站点刷流】已删除种子 xxx.2026.1080p.WEB-DL
【站点刷流】已删除种子 yyy.S01E03.2160p
【站点刷流】已删除种子 zzz.2025.BluRay
【站点刷流】已删除种子 ...
（一天几十上百条）
```

这个插件把它们**压成一条**，隔一段时间只告诉你「这段时间新增几个、删除几个、还剩几个活跃」：

```
【刷流汇总】
近 2 小时 5 分钟
新增 12 个 · 删除 11 个
当前活跃 45 · 累计新增 854 / 删除 809
流量 ↑ 3.2 GB · ↓ 1.8 TB
```

### 它做什么，不做什么

- **做**：读刷流插件的统计，按你设的周期做差值汇总，推一条。
- **不做**：不刷流、不删种子、不动任何下载任务。它只是通知的压缩层，随时能关，关了刷流照跑。

### 功能

- **周期汇总**：CRON 自己写，10 分钟到每天一次都行。
- **只报增量**：算的是「距上次汇总以来的变化」，不是每轮重复播总数。
- **首次只报基线**：装上第一条是「已开始统计 + 当前累计」，不刷历史。
- **无变化不推送**：这段时间没新增没删除就跳过，时间窗继续累积（可以关）。
- **立即推送一次**：配置页勾一下保存，3 秒内推一条，用来验通知渠道通不通。
- **数据来源自动检测**：下拉框直接列本机已装的刷流插件，不用去翻 ID。
- **两种刷流插件都吃**：单任务版（`BrushFlowLowFreq`）和多任务版（`BrushFlow`）。

## 环境要求

- MoviePilot **v2 系列**（索引在 `package.v2.json`，只支持 V2 宿主，V3 没适配）
- Python 3.8+，用宿主已有的 `apscheduler`、`pytz`，**没有额外第三方依赖**

## 安装

### 方式一：加进插件市场（推荐）

在 MoviePilot 的 `config/app.env` 里找到 `PLUGIN_MARKET`，把本仓库用英文逗号追加到末尾：

```ini
PLUGIN_MARKET='https://github.com/jxxghp/MoviePilot-Plugins,https://github.com/IceNoproblem/MoviePilot-Plugins'
```

重启容器，到「插件市场」搜 **刷流汇总** 就能装。

> 已经有别的仓库地址的，直接在原来的值后面加 `,https://github.com/IceNoproblem/MoviePilot-Plugins`，别删原来的。

### 方式二：手动放文件

把 `plugins.v2/brushdigest/` 整个目录拷到 MoviePilot 容器的 `/app/app/plugins/brushdigest/`：

```bash
docker cp plugins.v2/brushdigest moviepilot-v2:/app/app/plugins/brushdigest
docker exec moviepilot-v2 chown -R moviepilot:moviepilot /app/app/plugins/brushdigest
docker restart moviepilot-v2
```

再到「插件」页启用。**注意** `/app` 在容器里，镜像更新或容器重建就没了，得重新拷；插件数据（快照）存在数据库，不会丢。

## 配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 启用插件 | 关 | 总开关 |
| 发送通知 | 开 | 关掉只写日志不推送（可以拿来看数据对不对） |
| 无变化不推送 | 开 | 区间里没新增没删除就跳过这次 |
| 显示流量 | 开 | 消息里带上这段时间的上传/下载增量 |
| 汇总周期 | `*/10 * * * *` | CRON，默认每 10 分钟 |
| 数据来源插件 | 自动检测 | 下拉框选，会自动列出本机已装的刷流插件 |
| 立即推送一次 | 关 | 勾上保存就推一条，自测用，推完自动复位 |

### ⚠️ 关键一步：关掉原刷流插件的通知

**必须做**，不然每个种子照旧单独推，汇总就白做了。

1. **BrushFlowLowFreq（低频版）**：插件设置页 → 取消勾选「发送通知」→ 保存。
2. **BrushFlow（多任务版）**：设置页 → 任务列表里**逐个编辑每个任务** → 关掉该任务的「发送通知」→ 保存。
3. 两个都装了的话，**两个都要关**（哪个在用关哪个）。关的是通知不是刷流，刷流照常跑。

关完，通知就只由这个插件按周期统一发。

### 周期怎么配

刷流插件自己有执行周期（比如每 2 小时），汇总比它短没意义。常见两种：

```ini
0 */2 * * *    # 跟刷流节奏，每 2 小时一条
0 9 * * *      # 每天早上 9 点一条，最省事
```

## 数据是怎么来的

插件不自己统计，只读刷流插件算好的结果：

- 单任务版：读插件数据里的 `statistic` 键。
- 多任务版：读 `task.<任务ID>.statistic`，所有任务加总。

每次汇总把当前值和上次快照（存在本插件自己的数据里）相减，得到区间增量。所以：

- **第一次运行**没有快照，只报当前累计值当基线。
- 刷流插件被停用或清空统计（累计数变小）时，增量按 0 处理，不会出负数。

## 常见问题

**装了但市场里搜不到？**
`PLUGIN_MARKET` 改完要**重启容器**；再确认地址后面没多余空格，多个地址之间是英文逗号。

**汇总数字和刷流插件页面对不上？**
本插件报的是区间增量，刷流插件页面显示的是累计值。累计 = 上次基线 + 各区间增量之和，一致的，只是口径不同。

**一直没收到推送？**
按顺序查：① 插件启用了吗；②「发送通知」开着吗；③「无变化不推送」是不是因为这段时间真没新增删除；④ 用「立即推送一次」自测，看是插件问题还是通知渠道问题。

**换了刷流插件（低频版换多任务版）要注意什么？**
换完累计基数会变，第一次汇总可能显示 0 增量（新值比旧快照小），正常。想干净重启，跑一次「立即推送一次」让快照对齐新数据源。

**支持 MoviePilot V3 吗？**
暂时不适配。索引里标了 `"v3": false`，V3 环境不会给安装入口。
