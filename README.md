# 刷流汇总（BrushDigest）

如果你开了「站点刷流」插件，手机大概率是这种状态：

```
【站点刷流】已删除种子 xxx.2026.1080p.WEB-DL
【站点刷流】已删除种子 yyy.S01E03.2160p
【站点刷流】已删除种子 zzz.2025.BluRay
【站点刷流】已删除种子 ...
（一天几十上百条）
```

这个插件把它们**压成一条**，每隔一段时间只告诉你「这段时间新增几个、删除几个、还剩几个活跃」：

```
【刷流汇总】
近 2 小时 5 分钟
新增 12 个 · 删除 11 个
当前活跃 45 · 累计新增 854 / 删除 809
流量 ↑ 3.2 GB · ↓ 1.8 TB
```

## 它做什么，不做什么

- **做**：读取刷流插件的统计数据，按你设定的周期做差值汇总，推一条消息。
- **不做**：不刷流、不删种子、不改动任何下载任务。它只是「通知的压缩层」，随时可以关掉，不影响刷流本身。

## 功能

- **周期汇总**：CRON 表达式自定义，10 分钟到每天一次都行。
- **只报增量**：统计的是「距上次汇总以来的变化」，不是每轮重复播报总数。
- **首次运行只报基线**：装上后第一条消息是「已开始统计 + 当前累计」，避免刷屏历史数据。
- **无变化不推送**：这段时间没新增没删除就直接跳过，时间窗继续累积（可关闭）。
- **立即推送一次**：配置页勾一下保存，3 秒内推一条，用来验证通知渠道是否通。
- **数据来源自动检测**：下拉框直接列出本机已装的刷流插件，不用去翻插件 ID。
- **兼容两种刷流插件**：单任务版（`BrushFlowLowFreq`）和 多任务版（`BrushFlow`）。

## 环境要求

- MoviePilot **v2 系列**（插件索引在 `package.v2.json`，仅支持 V2 宿主，V3 未适配）
- Python 3.8+（用到宿主已有的 `apscheduler`、`pytz`，**无额外第三方依赖**）

## 安装

### 方式一：加进插件市场（推荐）

在 MoviePilot 的 `config/app.env` 里找到 `PLUGIN_MARKET`，把本仓库地址用英文逗号追加到末尾：

```ini
PLUGIN_MARKET='https://github.com/jxxghp/MoviePilot-Plugins,https://github.com/IceNoproblem/MoviePilot-Plugins'
```

重启容器后，到「插件市场」搜索 **刷流汇总** 即可一键安装。

> 市场上已有其他仓库地址的，直接在原来的值后面加 `,https://github.com/IceNoproblem/MoviePilot-Plugins`，不要删掉原来的。

### 方式二：手动放文件

把 `plugins.v2/brushdigest/` 整个目录拷到 MoviePilot 容器的 `/app/app/plugins/brushdigest/`：

```bash
docker cp plugins.v2/brushdigest moviepilot-v2:/app/app/plugins/brushdigest
docker exec moviepilot-v2 chown -R moviepilot:moviepilot /app/app/plugins/brushdigest
docker restart moviepilot-v2
```

再到「插件」页面启用它。**注意**：`/app` 在容器内，镜像更新或容器重建后会丢失，需要重新拷贝；插件数据（快照）存在数据库里，不会丢。

## 配置

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 启用插件 | 关 | 总开关 |
| 发送通知 | 开 | 关掉后只写日志不推送（可以用来看数据对不对） |
| 无变化不推送 | 开 | 区间内没有新增/删除就跳过这次推送 |
| 显示流量 | 开 | 消息里附带这段时间的上传/下载增量 |
| 汇总周期 | `*/10 * * * *` | CRON 表达式，默认每 10 分钟 |
| 数据来源插件 | 自动检测 | 从下拉框选择，会自动列出本机已装的刷流插件 |
| 立即推送一次 | 关 | 勾选保存后立即推一条，用于自测，推完自动复位 |

### ⚠️ 关键一步：关掉原刷流插件的通知

**必须做**，否则每个种子照旧单独推送，汇总就白做了。

1. **BrushFlowLowFreq（低频版）**：插件设置页 → 取消勾选「发送通知」→ 保存。
2. **BrushFlow（多任务版）**：设置页 → 任务列表里**逐个编辑每个任务** → 关掉该任务的「发送通知」→ 保存。
3. 两个都装了的话，**两个都要关**（哪个在用关哪个）。关掉的是通知，不是刷流，刷流照常跑。

关完之后，通知就只由本插件按周期统一发出。

### 推荐的周期搭配

刷流插件本身有执行周期（比如每 2 小时），汇总周期比它短没意义。常见两种：

```ini
0 */2 * * *    # 跟着刷流节奏，每 2 小时一条
0 9 * * *      # 每天早上 9 点一条，最省事
```

## 数据是怎么来的

插件不自己统计，只读刷流插件已经算好的结果：

- 单任务版：读插件数据里的 `statistic` 键。
- 多任务版：读 `task.<任务ID>.statistic`，把所有任务加总。

每次汇总时把当前值和上次快照（存在本插件自己的数据里）相减，得到这段区间的增量。所以：

- **第一次运行**没有快照，只报当前累计值作为基线。
- 如果刷流插件被停用或清空统计（累计数变小），增量会按 0 处理，不会出现负数。

## 常见问题

**Q：装了但市场里搜不到？**
`PLUGIN_MARKET` 改完要**重启容器**；另外确认地址后面没有多余空格，多个地址之间是英文逗号。

**Q：汇总数字和刷流插件页面对不上？**
本插件报的是「区间增量」，刷流插件页面显示的是「累计值」。累计 = 上次基线 + 各区间增量之和，两者是一致的，只是口径不同。

**Q：一直没收到推送？**
按顺序查：① 插件是否启用；②「发送通知」是否开着；③「无变化不推送」是否因为这段时间真的没有新增删除；④ 用「立即推送一次」自测，看是插件问题还是通知渠道问题。

**Q：换了刷流插件（比如从低频版换到多任务版）要注意什么？**
换完之后累计值基数会变，第一次汇总可能显示 0 增量（因为新值比旧快照小），属正常现象。想干净重启的话，把本插件的「立即推送一次」跑一次，让快照对齐新数据源。

**Q：支持 MoviePilot V3 吗？**
暂不适配。索引里已标记 `"v3": false`，V3 环境不会提供安装入口。
